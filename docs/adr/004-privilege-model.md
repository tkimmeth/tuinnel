# ADR-004: Replace blanket `NOPASSWD` sudoers with a root-owned helper

**Status:** Proposed
**Date:** 2026-05-09
**Related:** ADR-001, ADR-003

## Context

`wg-quick` and `nft` need root. tuinnel currently asks the kernel for root via `sudo`, and the README + `install.sh` recommend the entry:

```
%wheel ALL=(root) NOPASSWD: /usr/bin/wg-quick, /usr/bin/wg, /usr/bin/nft
```

This is convenient. It is also a documented root-RCE primitive. Two reasons:

1. **`wg-quick` interprets the `.conf` file as more than data.** `PostUp = `, `PostDown = `, `PreUp = `, `PreDown = ` and (less commonly) `Table = `, `FwMark = ` are evaluated by `bash` as root. Because tuinnel reads configs from `~/.config/tuinnel/servers/` (a `0755`, user-writable directory), any process running as the user that can drop a file there gets a no-password root shell on the next connect. That includes a malicious AUR PKGBUILD, a compromised browser extension, a cargo build script, a `.zip` from a typo-squatted "VPN server pack" repo, or an attacker who already has user-level RCE and wants to escalate.
2. **`NOPASSWD: /usr/bin/nft` is not "permission to manage one table."** It is "permission to run arbitrary `nft` commands." That includes `nft flush ruleset` (drops the host firewall), `nft -f /any/file` (load arbitrary rulesets, including DNAT redirects pointing at an attacker), and read access to every rule on the host.

Removing `NOPASSWD` entirely makes every `tuinnel connect` block on a password prompt — the autoconnect systemd unit becomes unusable. We need a model that is both passwordless and refuses the dangerous primitives.

## Decision

Introduce a root-owned helper at `/usr/local/libexec/tuinnel-helper` (mode `0755`, owner `root:root`) with a finite enum of actions. The helper is the only binary tuinnel asks `sudo` (or `pkexec`) to run.

Helper interface:

```
tuinnel-helper up    <config-stem>          # bring up by stem, helper resolves to /etc/tuinnel/configs/<stem>.conf
tuinnel-helper down  <iface>                # bring down by interface name (validated)
tuinnel-helper ks-up                        # load the fixed ruleset
tuinnel-helper ks-down                      # remove the tuinnel_killswitch table
```

Helper rules:

1. **Config files live in a root-owned directory** (`/etc/tuinnel/configs/`, mode `0700`, owner `root:root`). `tuinnel install <path>` (a new subcommand) copies a user-supplied `.conf` into that directory after validating it.
2. **Validation rejects** any line whose key (case-insensitive, after whitespace trimming) is one of `postup`, `postdown`, `preup`, `predown`, `table`, `fwmark`, `saveconfig`.
3. **Path canonicalization** confines arguments to the helper-managed directory. The helper takes a stem, not a path, to remove path-traversal entirely.
4. **Interface name validation** — `^[a-zA-Z0-9_-]{1,15}$` (Linux `IFNAMSIZ`).
5. **Kill-switch ruleset is a fixed file** (`/etc/tuinnel/killswitch.nft`) regenerated by the helper from a template + the active session's interface and endpoint. The user-mode tuinnel never writes a ruleset to a path `nft` will read.
6. **Sudoers narrows to one binary**: `%wheel ALL=(root) NOPASSWD: /usr/local/libexec/tuinnel-helper`.

Preferred long-term: replace `sudo` with **polkit** (`pkexec`) and ship `/usr/share/polkit-1/actions/com.tuinnel.policy` with three actions. Polkit logs every authorization to journalctl with the invoking PID/UID; sudo `NOPASSWD` is silent. We use polkit when we ship to AUR; sudo is acceptable for the `cargo install` path.

## Consequences

- The "drop a `.conf` and you get root" attack class is closed: the helper rejects PostUp/PostDown configs, and the user no longer has write access to the directory `wg-quick` reads from.
- `nft` privilege shrinks from "the firewall" to "one table, one ruleset, two operations." `nft flush ruleset` is no longer reachable.
- The user has to run a one-time `sudo tuinnel install` (or equivalent) per `.conf`. We accept that small UX cost in exchange for closing the attack surface.
- `install.sh` ships the helper to `/usr/local/libexec/`, sets ownership/perms, drops the sudoers entry. The new sudoers file replaces `tuinnel`'s old `NOPASSWD: wg-quick, wg, nft` line.
- `cargo install tuinnel` (no install.sh) leaves the user without the helper — `tuinnel` detects this in `doctor` and refuses to operate without password prompts. Documented in README.
- Backwards compatibility: existing users with the old sudoers line keep working until they re-run `install.sh` (which removes the old entry and writes the new one).
- This ADR depends on validation logic also living in the Rust binary (`src/wireguard.rs::validate_wg_config`) — defense in depth for the `cargo run` development case where the helper isn't installed.
